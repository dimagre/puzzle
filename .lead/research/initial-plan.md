## Roadmap: фази та фічі

### Phase 1 — Foundation (тижні 1-2)

Мета: працюючий скелет з базовим каталогом.

- Scaffolding: Next.js 14 App Router, TypeScript strict, Prisma + PostgreSQL, Tailwind
- Auth: JWT з HTTP-only cookies (реєстрація, логін, logout, refresh)
- DB schema: users, puzzles, categories, images
- Каталог пазлів: список з фільтрами (категорія, кількість деталей, стан, тип)
- Сторінка пазла з галереєю зображень
- Оптимізація зображень (Sharp: resize, WebP, auto-rotate) при upload
- i18n каркас (uk/en) з перемикачем
- Адаптивний layout (mobile-first)
- Admin: CRUD пазлів (тільки адмін може створювати)

### Phase 2 — Commerce (тижні 3-4)

Мета: оренда, кошик, замовлення.

- Оренда з депозитом (ціни в ₴, конфігурація тарифів)
- Безкоштовні пазли та обмін (окремий flow)
- Кошик та оформлення замовлення
- Профіль користувача з адресою доставки (область, місто, відділення НП)
- Вибір доставки: Нова Пошта, Укрпошта, самовивіз (склад Київ), самовивіз від продавця
- Admin: управління замовленнями (статуси, трек-номер, нотатки)

### Phase 3 — Integrations & Tracking (тижні 5-6)

Мета: реальна доставка, сповіщення, інвентаризація.

- Інтеграція Nova Poshta API (відділення, тарифи, ТТН)
- Інтеграція Ukrposhta API
- Telegram bot: сповіщення про замовлення (новий, статус, доставлено)
- Відстеження пазлів: де зараз, у кого, історія переміщень
- QR-код генерація, завантаження, друк з адмін-панелі
- Інвентаризація (QR-код, стан, лічильник прокатів)
- Захист від видалення пазлів з активними замовленнями

### Phase 4 — Admin & Polish (тиждень 7)

Мета: аналітика, аудит, production-ready.

- Панель адміна з аналітикою (користувачі, замовлення, дохід)
- Журнал активності (аудит-лог дій з пазлами та замовленнями)
- Приховування/показ оголошень
- SEO, performance audit, error handling
- CI/CD, Docker, deployment

## Варіанти дизайн-рішень (потребують вибору)

### A. Auth provider

| Варіант | Плюси | Мінуси |
|---------|-------|--------|
| Custom JWT (як у spec) | Повний контроль, без залежностей | Більше коду, треба самим робити refresh/revoke |
| NextAuth.js + JWT strategy | Швидше, proven patterns, social login ready | Додаткова залежність, менше контролю |

Рекомендація: **Custom JWT** — ти вказав це в spec, і для MVP без social login це простіше.

### B. Image storage

| Варіант | Плюси | Мінуси |
|---------|-------|--------|
| Cloudflare R2 | Дешево, S3-compatible, CDN з коробки | Потрібен Cloudflare account |
| Vercel Blob | Zero-config якщо на Vercel | Дорожче при масштабі |
| Local + nginx | Безкоштовно на VPS | Треба backup, CDN окремо |

Рекомендація: залежить від hosting (питання 7).

### C. Nova Poshta інтеграція

| Варіант | Плюси | Мінуси |
|---------|-------|--------|
| Тільки довідник відділень (API) | Простіше, достатньо для вибору відділення | Без автоматичного створення ТТН |
| Повна інтеграція (ТТН, трекінг) | Автоматизація доставки | Складніше, потрібен бізнес-акаунт НП |

Рекомендація: Phase 1-2 — тільки довідник. Phase 3 — повна інтеграція якщо є бізнес-акаунт.
